Supports the special value 'last' which resolves to the highest turn number.\"\n134\t    }\n135\t  },\n136\t  \"required\": [\"extraction_dir\", \"category\"],\n137\t  \"additionalProperties\": false\n138\t}\n139\t```\n140\t\n141\t#### Parameters\n142\t\n143\t| Parameter | Type | Required | Description |\n144\t|---|---|---|---|\n145\t| `extraction_dir` | `string` | Yes | Absolute path to the extraction output directory. |\n146\t| `category` | `string` | Yes | One of the five query categories described in Section 5. |\n147\t| `turns` | `(integer \\| \"last\")[]` | Conditional | Required when `category` is `\"tracked_state\"` or `\"turn_detail\"`. Ignored for other categories. `\"last\"` resolves to the highest turn number. Can be mixed: `[1, \"last\"]`. |\n148\t\n149\t#### Return Value\n150\t\n151\t| Field | Type | Description |\n152\t|---|---|---|\n153\t| `success` | `boolean` | Whether the query completed without error. |\n154\t| `category` | `string` | The category that was queried (echoed back). |\n155\t| `data` | `object \\| array` | The query result. Structure varies by category (see Section 5). |\n156\t| `error` | `string \\| null` | Error message if `success` is `false`. `null` on success. |\n157\t\n158\t---\n159\t\n160\t## 3. Parser Design\n161\t\n162\tThe parsing pipeline consists of four sequential phases. Each phase's output feeds the next.\n163\t\n164\t### 3.1 Phase 1: Multi-File Combining\n165\t\n166\tWhen the tool receives multiple input files, it produces a single unified document before parsing begins.\n167\t\n168\t**Algorithm:**\n169\t\n170\t1. For each input file path, call `stat()` to obtain the file's modification timestamp (`mtime`).\n171\t2. Sort files by `mtime` ascending.\n172\t3. Read each file's full text content into memory, preserving original line numbers per file.\n173\t4. **Header metadata resolution:** Extract header metadata (title, story background, character name/background/skills) from the **most recently modified file only**.\n174\t5. **Turn collection:** Scan every file for turn blocks (delimited by `-- Turn N --`). Collect all turns into a map keyed by turn number. If the same turn number appears in multiple files, the version from the file with the later mtime wins.\n175\t6. Sort the combined turn map by turn number ascending.\n176\t7. **Manifest generation:** Record which files contributed which turns, and which turns were overridden.\n177\t\n178\t**Output:** A combined header text block, an ordered list of turn text blocks with source file + line range metadata, and the manifest.\n179\t\n180\t### 3.2 Phase 2: Header Parsing\n181\t\n182\tHeader parsing uses a line-by-line state machine that processes text from the beginning of the document up to the first `-- Turn 1 --` delimiter.\n183\t\n184\t#### Structural Markers\n185\t\n186\t| Marker | Regex Pattern | Captures |\n187\t|--------|--------------|----------|\n188\t| Title | `/^==\\s*(.+?)\\s*==$/` on first non-empty line | Title string |\n189\t| Story Background | `/^-- Story Background --$/` | All text until next `-- ... --` header |\n190\t| Character block | `/^-- Character --$/` | Enters character sub-parser |\n191\t| Objective | `Your objective for this adventure is:` between `- - - - -` dividers | Objective text (extracted during Turn 1 parsing, stored as header metadata) |\n192\t\n193\t#### State Machine\n194\t\n195\t```\n196\tINIT → TITLE → SEEKING_SECTION → STORY_BACKGROUND → SEEKING_SECTION\n197\t                                → CHARACTER → (sub-states) → SEEKING_SECTION\n198\t                                → DONE (on Turn 1 delimiter)\n199\t```\n200\t\n201\t#### Character Sub-Parser\n202\t\n203\tWithin the `CHARACTER` state, subsections are detected by the **subsection header pattern**: a text line followed immediately by a line of 4+ dashes.\n204\t\n205\t| Subsection | Captures |\n206\t|-----------|----------|\n207\t| `Name` | Character name (typically single line) |\n208\t| `Background` | Character background (may be multi-paragraph) |\n209\t| `Skills` | Lines matching `/^(.+?):\\s*(\\d+)\\s*\\(([^)]+)\\)$/` → skill name, numeric rating, level label |\n210\t\n211\tThe character sub-parser exits when it encounters a `-- ... --` header that is not a recognized subsection.\n212\t\n213\t#### Objective Extraction\n214\t\n215\tThe objective appears inside Turn 1's content (not in the pre-turn header area):\n216\t\n217\t1. Locate `- - - - -` divider line within Turn 1.\n218\t2. Find `Your objective for this adventure is:` line.\n219\t3. Capture text until the closing `- - - - -` divider.\n220\t4. If not found, set objective to `null`.\n221\t\n222\t### 3.3 Phase 3: Turn Parsing\n223\t\n224\t#### Turn Splitting\n225\t\n226\t**Turn delimiter regex:** `/^-- Turn (\\d+) --$/m`\n227\t\n228\tRequirements: line begins with `-- Turn `, followed by one or more digits, followed by ` --`, with nothing else on the line. Always preceded and followed by blank lines.\n229\t\n230\tFor each match, the turn block spans from the delimiter to the next delimiter or EOF. Line ranges (start/end in original file) are recorded for drill-down support.\n231\t\n232\t#### Turn State Machine\n233\t\n234\t| State | Entry Marker | Exit |\n235\t|-------|-------------|------|\n236\t| `ACTION` | `Action\\n------` (text line + 4+ dashes) | Next section marker or turn boundary |\n237\t| `OUTCOME` | `Outcome\\n-------` | Next section marker or turn boundary |\n238\t| `SECRET_INFO` | `Secret Information\\n------------------` | Next section marker or turn boundary |\n239\t| `TRACKED` | `Tracked Items\\n-------------` | `Hidden Tracked Items` header or turn boundary |\n240\t| `HIDDEN_TRACKED` | `Hidden Tracked Items\\n--------------------` | Turn boundary or EOF |\n241\t\n242\tSection markers are detected by the two-line pattern: text line immediately followed by a line of 4+ dashes. Sections can appear in any order; the parser does not enforce ordering.\n243\t\n244\t**Turn 1 special handling:** Turn 1 has no `Action` section (the first narrative section is `Outcome`). The objective block is extracted from Turn 1 and stored as header metadata.\n245\t\n246\t#### Turn Output\n247\t\n248\tEach turn produces: `{ turn_number, action, outcome, secret_info, tracked_items, hidden_tracked_items, source: { file, start_line, end_line } }`\n249\t\n250\t### 3.4 Phase 4: Generic Tracked Items Parsing\n251\t\n252\tApplies identically to both `TRACKED` and `HIDDEN_TRACKED` content. The parser treats tracked items as an opaque key-value store.\n253\t\n254\t#### Item Header Detection\n255\t\n256\t**Pattern:** `/^[^\\n:]+:\\s*$/m`\n257\t\n258\tA line is an item header if and only if it ends with a colon followed by optional whitespace and end-of-line, with no other content after the colon.\n259\t\n260\t**Critical discriminator:** Lines like `Lilith: Intelligent, Cruel, Ambitious` have content after the colon — these are sub-entries within a value, NOT new item headers.\n261\t\n262\t| Line | Item Header? | Reason |\n263\t|------|:---:|--------|\n264\t| `ViviDevelopment:` | Yes | Colon at end, nothing after |\n265\t| `Traits:` | Yes | Colon at end, nothing after |\n266\t| `Current Date:` | Yes | Colon at end, nothing after |\n267\t| `Lilith: Intelligent, Cruel` | No | Content after colon |\n268\t| `Gold: 500` | No | Content after colon |\n269\t\n270\t#### Splitting Algorithm\n271\t\n272\t1. Split section text on `\\n\\n` (blank line) followed by a line matching the item header pattern.\n273\t2. For each segment: first line is the key (strip trailing colon), remainder is the value (trimmed).\n274\t3. Empty values stored as `\"\"`.\n275\t\n276\tThis preserves blank lines within multi-line values (e.g., character trait lists separated by double blank lines within a Traits item) because the lines after those internal blanks have content after their colons and thus don't match the item header pattern.\n277\t\n278\t#### Edge Cases\n279\t\n280\t| Case | Behavior |\n281\t|------|----------|\n282\t| Turn has no tracked items section | Return `null` |\n283\t| Section exists but empty | Return `{}` |\n284\t| Item header with no value | Store as `\"\"` |\n285\t| Value contains internal blank lines | Preserved; only blanks before item headers trigger splits |\n286\t\n287\t### 3.5 Delimiter Collision Analysis\n288\t\n289\tEach delimiter has been validated against narrative prose across five tested exports totaling 349 turns. Zero false positives observed.\n290\t\n291\t| Delimiter | Why Collision Is Implausible |\n292\t|-----------|------------------------------|\n293\t| `-- Turn N --` | Requires literal \"Turn\" + bare integer between dashes on an empty line. Prose like \"-- Turn around --\" has no bare integer. |\n294\t| Section headers (`Action\\n------`) | Requires a bare keyword on its own line immediately followed by a line of only dashes. Does not occur in natural prose. |\n295\t| Item header (`Word:\\s*$`) | Requires colon at end-of-line with nothing after. In prose, colons are followed by content. |\n296\t| Title (`== ... ==`) | Only tested on first non-empty line of document. |\n297\t| Objective divider (`- - - - -`) | Only checked within Turn 1. |\n298\t\n299\t**Mitigation for future collisions:** If adversarial content produces false positives, add contextual validation (e.g., turn number within expected range, section markers appearing in structurally plausible positions).\n300\t\n301\t### 3.6 Error Handling\n302\t\n303\t| Condition | Severity | Behavior |\n304\t|-----------|----------|----------|\n305\t| File not found or unreadable | Error | Halt with OS error. |\n306\t| No title found | Warning | Set `title` to `null`. |\n307\t| No `-- Turn 1 --` in any file | Error | Halt — no parseable turns. |\n308\t| Turn number gap | Warning | Record missing numbers. Continue. |\n309\t| Turn 1 has Action section | Warning | Accept and store. |\n310\t| Duplicate turn after combining | Error | Bug in Phase 1. |\n311\t| Section appears twice in one turn | Warning | Append content with `\\n\\n`. |\n312\t\n313\tAll warnings include source file, line number, and description.\n314\t\n315\t---\n316\t\n317\t## 4. Query Categories\n469\t\n470\t### 5.1 manifest\n471\t\n472\tReturns full `manifest.json` content. Recommended first query — tells the agent what data is available, how many turns exist, and which files were produced.\n473\t\n474\t### 5.2 metadata\n475\t\n476\tReturns full `metadata.json` content. Primary source for Title, Description, Background, Skills, and Objective fields in a sequel world.\n477\t\n478\t### 5.3 tracked_state\n479\t\n480\t**Requires `turns` parameter.** For each requested turn, finds the snapshot where `from_turn <= turn <= to_turn` and returns that snapshot's data.\n481\t\n482\tReturns an array of objects:\n483\t\n484\t```json\n485\t[\n486\t  {\n487\t    \"turn\": 15,\n488\t    \"tracked_items\": { \"ViviDevelopment\": \"6\", \"VivianPersonality\": \"Vivian-dominant\" },\n489\t    \"hidden_tracked_items\": { \"Suspicion\": \"0\", \"InvestigationInterest\": \"0\" }\n490\t  }\n491\t]\n492\t```\n493\t\n494\tIf `tracked_state.json` does not exist, returns an error indicating tracked state is not available.\n495\t\n496\t### 5.4 turn_index\n497\t\n498\tReturns full `turn_index.json` content. The agent uses this to scan turn previews and identify turns of interest before drilling in with `turn_detail`.\n499\t\n500\t### 5.5 turn_detail\n501\t\n502\t**Requires `turns` parameter.** Reads specific turns from the original export file using line ranges from the turn index.\n503\t\n504\tReturns an array of objects:\n505\t\n506\t```json\n507\t[\n508\t  {\n509\t    \"turn\": 1,\n510\t    \"action\": null,\n511\t    \"outcome\": \"Full outcome text...\",\n512\t    \"secret_info\": \"Full secret info text...\"\n513\t  }\n514\t]\n515\t```\n516\t\n517\tIf the original source file has been moved or deleted since extraction, returns an error.\n518\t\n519\t### 5.6 The `\"last\"` Alias\n520\t\n521\tAll categories accepting `turns` support `\"last\"`, which resolves to the highest turn number. Limitations\n571\t\n572\t### What Deterministic Parsing Cannot Do\n573\t\n574\t1. **Cannot summarize narrative arcs.** The agent still reads prose — but now reads targeted turns instead of everything.\n575\t2. **Cannot extract character rosters from prose.** For exports without structured character data in tracked items (like RingOfDis), the agent must read Secret Info via `turn_detail` and identify characters itself.\n576\t3. **Cannot determine character relationships.** Relationships are expressed in narrative, not structure.\n577\t4. **Cannot detect theme or tone.** Semantic properties of prose, not parseable.\n578\t\n579\t### Where It Helps Most\n580\t\n581\t- **Eliminates \"read the ENTIRE export.\"** Context usage drops by an order of magnitude.\n582\t- **Prevents hallucination of tracked item values.** Exact final state from the parser, not the agent's fuzzy recall.\n583\t- **Prevents early/late state confusion.** Per-turn snapshots show what was true when.\n584\t- **Prevents character name confusion.** Tracked item strings are exact as written.\n585\t\n586\t### Edge Cases\n587\t\n588\t| Scenario | Behavior |\n589\t|---|---|\n590\t| Export with no tracked items (RingOfDis) | `tracked_state.json` not written. One-entry turn index. |\n592\t| Malformed turn delimiters | Parser extracts what it can. Warnings in manifest. |\n593\t| Empty tracked item values | Stored as `\"\"`. |\n594\t| Very long tracked item values | Stored verbatim, no truncation. |\n595\t\n596\t---\n597\t\n598\t## 8. If the directory already contains output from a previous extraction, those files are overwritten. |\n90\t\n91\t#### Return Value\n92\t\n93\tReturns a JSON object summarizing the extraction results:\n94\t\n95\t| Field | Type | Description |\n96\t|---|---|---|\n97\t| `success` | `boolean` | Whether extraction completed without error. |\n98\t| `total_turns` | `number` | Total number of unique turns extracted across all input files. |\n99\t| `turn_range` | `[number, number]` | The first and last turn numbers found. |\n100\t| `input_files_processed` | `number` | Number of input files that were successfully read and parsed. |\n101\t| `has_tracked_items` | `boolean` | Whether tracked items were found. |\n102\t| `has_hidden_tracked_items` | `boolean` | Whether hidden tracked items were found. |\n103\t| `files_written` | `string[]` | Filenames of all output JSON files written to `extraction_dir`. |\n104\t| `warnings` | `string[]` | Non-fatal issues encountered during parsing. Empty array if none. |\n105\t\n106\t### 2.2 `query_story_data`\n107\t\n108\tReads previously extracted story data and returns the requested slice. There is **no \"all\" category** — the agent must make targeted queries for the specific data it needs.\n109\t\n110\t#### Input Schema\n111\t\n112\t```json\n113\t{\n114\t  \"type\": \"object\",\n115\t  \"properties\": {\n116\t    \"extraction_dir\": {\n117\t      \"type\": \"string\",\n118\t      \"description\": \"Absolute path to the directory containing extracted story data (same path passed to extract_story_data).\"\n119\t    },\n120\t    \"category\": {\n121\t      \"type\": \"string\",\n122\t      \"enum\": [\"manifest\", \"metadata\", \"tracked_state\", \"turn_index\", \"turn_detail\"],\n123\t      \"description\": \"The category of data to retrieve.\"\n124\t    },\n125\t    \"turns\": {\n126\t      \"type\": \"array\",\n127\t      \"items\": {\n128\t        \"oneOf\": [\n129\t          { \"type\": \"integer\", \"minimum\": 1 },\n130\t          { \"type\": \"string\", \"enum\": [\"last\"] }\n131\t        ]\n132\t      },\n133\t      \"description\": \"Turn number(s) to query. Supports the special value 'last' which resolves to the highest turn number.\"\n134\t    }\n135\t  },\n136\t  \"required\": [\"extraction_dir\", \"category\"],\n137\t  \"additionalProperties\": false\n138\t}\n139\t```\n140\t\n141\t#### Parameters\n142\t\n143\t| Parameter | Type | Required | Description |\n144\t|---|---|---|---|\n145\t| `extraction_dir` | `string` | Yes | Absolute path to the extraction output directory. |\n146\t| `category` | `string` | Yes | One of the five query categories described in Section 5. |\n147\t| `turns` | `(integer \\| \"last\")[]` | Conditional | Required when `category` is `\"tracked_state\"` or `\"turn_detail\"`. Ignored for other categories. `\"last\"` resolves to the highest turn number. Can be mixed: `[1, \"last\"]`. |\n148\t\n149\t#### Return Value\n150\t\n151\t| Field | Type | Description |\n152\t|---|---|---|\n153\t| `success` | `boolean` | Whether the query completed without error. |\n154\t| `category` | `string` | The category that was queried (echoed back). |\n155\t| `data` | `object \\| array` | The query result. Structure varies by category (see Section 5). |\n156\t| `error` | `string \\| null` | Error message if `success` is `false`. `null` on success. |\n157\t\n158\t---\n159\t\n160\t## 3. Parser Design\n161\t\n162\tThe parsing pipeline consists of four sequential phases. Each phase's output feeds the next.\n163\t\n164\t### 3.1 Phase 1: Multi-File Combining\n165\t\n166\tWhen the tool receives multiple input files, it produces a single unified document before parsing begins.\n167\t\n168\t**Algorithm:**\n169\t\n170\t1. For each input file path, call `stat()` to obtain the file's modification timestamp (`mtime`).\n171\t2. Sort files by `mtime` ascending.\n172\t3. Read each file's full text content into memory, preserving original line numbers per file.\n173\t4. **Header metadata resolution:** Extract header metadata (title, story background, character name/background/skills) from the **most recently modified file only**.\n174\t5. **Turn collection:** Scan every file for turn blocks (delimited by `-- Turn N --`). Collect all turns into a map keyed by turn number. If the same turn number appears in multiple files, the version from the file with the later mtime wins.\n175\t6. Sort the combined turn map by turn number ascending.\n176\t7. **Manifest generation:** Record which files contributed which turns, and which turns were overridden.\n177\t\n178\t**Output:** A combined header text block, an ordered list of turn text blocks with source file + line range metadata, and the manifest.\n179\t\n180\t### 3.2 Phase 2: Header Parsing\n181\t\n182\tHeader parsing uses a line-by-line state machine that processes text from the beginning of the document up to the first `-- Turn 1 --` delimiter.\n183\t\n184\t#### Structural Markers\n185\t\n186\t| Marker | Regex Pattern | Captures |\n187\t|--------|--------------|----------|\n188\t| Title | `/^==\\s*(.+?)\\s*==$/` on first non-empty line | Title string |\n189\t| Story Background | `/^-- Story Background --$/` | All text until next `-- ... --` header |\n190\t| Character block | `/^-- Character --$/` | Enters character sub-parser |\n191\t| Objective | `Your objective for this adventure is:` between `- - - - -` dividers | Objective text (extracted during Turn 1 parsing, stored as header metadata) |\n192\t\n193\t#### State Machine\n194\t\n195\t```\n196\tINIT → TITLE → SEEKING_SECTION → STORY_BACKGROUND → SEEKING_SECTION\n197\t                                → CHARACTER → (sub-states) → SEEKING_SECTION\n198\t                                → DONE (on Turn 1 delimiter)\n199\t```\n200\t\n201\t#### Character Sub-Parser\n202\t\n203\tWithin the `CHARACTER` state, subsections are detected by the **subsection header pattern**: a text line followed immediately by a line of 4+ dashes.\n204\t\n205\t| Subsection | Captures |\n206\t|-----------|----------|\n207\t| `Name` | Character name (typically single line) |\n208\t| `Background` | Character background (may be multi-paragraph) |\n209\t| `Skills` | Lines matching `/^(.+?):\\s*(\\d+)\\s*\\(([^)]+)\\)$/` → skill name, numeric rating, level label |\n210\t\n211\tThe character sub-parser exits when it encounters a `-- ... --` header that is not a recognized subsection.\n212\t\n213\t#### Objective Extraction\n214\t\n215\tThe objective appears inside Turn 1's content (not in the pre-turn header area):\n216\t\n217\t1. Locate `- - - - -` divider line within Turn 1.\n218\t2. Find `Your objective for this adventure is:` line.\n219\t3. Capture text until the closing `- - - - -` divider.\n220\t4. If not found, set objective to `null`.\n221\t\n222\t### 3.3 Phase 3: Turn Parsing\n223\t\n224\t#### Turn Splitting\n225\t\n226\t**Turn delimiter regex:** `/^-- Turn (\\d+) --$/m`\n227\t\n228\tRequirements: line begins with `-- Turn `, followed by one or more digits, followed by ` --`, with nothing else on the line. Always preceded and followed by blank lines.\n229\t\n230\tFor each match, the turn block spans from the delimiter to the next delimiter or EOF. Line ranges (start/end in original file) are recorded for drill-down support.\n231\t\n232\t#### Turn State Machine\n233\t\n234\t| State | Entry Marker | Exit |\n235\t|-------|-------------|------|\n236\t| `ACTION` | `Action\\n------` (text line + 4+ dashes) | Next section marker or turn boundary |\n237\t| `OUTCOME` | `Outcome\\n-------` | Next section marker or turn boundary |\n238\t| `SECRET_INFO` | `Secret Information\\n------------------` | Next section marker or turn boundary |\n239\t| `TRACKED` | `Tracked Items\\n-------------` | `Hidden Tracked Items` header or turn boundary |\n240\t| `HIDDEN_TRACKED` | `Hidden Tracked Items\\n--------------------` | Turn boundary or EOF |\n241\t\n242\tSection markers are detected by the two-line pattern: text line immediately followed by a line of 4+ dashes. Sections can appear in any order; the parser does not enforce ordering.\n243\t\n244\t**Turn 1 special handling:** Turn 1 has no `Action` section (the first narrative section is `Outcome`). The objective block is extracted from Turn 1 and stored as header metadata.\n245\t\n246\t#### Turn Output\n247\t\n248\tEach turn produces: `{ turn_number, action, outcome, secret_info, tracked_items, hidden_tracked_items, source: { file, start_line, end_line } }`\n249\t\n250\t### 3.4 Phase 4: Generic Tracked Items Parsing\n251\t\n252\tApplies identically to both `TRACKED` and `HIDDEN_TRACKED` content. The parser treats tracked items as an opaque key-value store.\n253\t\n254\t#### Item Header Detection\n255\t\n256\t**Pattern:** `/^[^\\n:]+:\\s*$/m`\n257\t\n258\tA line is an item header if and only if it ends with a colon followed by optional whitespace and end-of-line, with no other content after the colon.\n259\t\n260\t**Critical discriminator:** Lines like `Lilith: Intelligent, Cruel, Ambitious` have content after the colon — these are sub-entries within a value, NOT new item headers.\n261\t\n262\t| Line | Item Header? | Reason |\n263\t|------|:---:|--------|\n264\t| `ViviDevelopment:` | Yes | Colon at end, nothing after |\n265\t| `Traits:` | Yes | Colon at end, nothing after |\n266\t| `Current Date:` | Yes | Colon at end, nothing after |\n267\t| `Lilith: Intelligent, Cruel` | No | Content after colon |\n268\t| `Gold: 500` | No | Content after colon |\n269\t\n270\t#### Splitting Algorithm\n271\t\n272\t1. Split section text on `\\n\\n` (blank line) followed by a line matching the item header pattern.\n273\t2. For each segment: first line is the key (strip trailing colon), remainder is the value (trimmed).\n274\t3. Empty values stored as `\"\"`.\n275\t\n276\tThis preserves blank lines within multi-line values (e.g., character trait lists separated by double blank lines within a Traits item) because the lines after those internal blanks have content after their colons and thus don't match the item header pattern.\n277\t\n278\t#### Edge Cases\n279\t\n280\t| Case | Behavior |\n281\t|------|----------|\n282\t| Turn has no tracked items section | Return `null` |\n283\t| Section exists but empty | Return `{}` |\n284\t| Item header with no value | Store as `\"\"` |\n285\t| Value contains internal blank lines | Preserved; only blanks before item headers trigger splits |\n286\t\n287\t### 3.5 Delimiter Collision Analysis\n288\t\n289\tEach delimiter has been validated against narrative prose across five tested exports totaling 349 turns. Zero false positives observed.\n290\t\n291\t| Delimiter | Why Collision Is Implausible |\n292\t|-----------|------------------------------|\n293\t| `-- Turn N --` | Requires literal \"Turn\" + bare integer between dashes on an empty line. Prose like \"-- Turn around --\" has no bare integer. |\n294\t| Section headers (`Action\\n------`) | Requires a bare keyword on its own line immediately followed by a line of only dashes. Does not occur in natural prose. |\n295\t| Item header (`Word:\\s*$`) | Requires colon at end-of-line with nothing after. In prose, colons are followed by content. |\n296\t| Title (`== ... ==`) | Only tested on first non-empty line of document. |\n297\t| Objective divider (`- - - - -`) | Only checked within Turn 1. |\n298\t\n299\t**Mitigation for future collisions:** If adversarial content produces false positives, add contextual validation (e.g., turn number within expected range, section markers appearing in structurally plausible positions).\n300\t\n301\t### 3.6 Error Handling\n302\t\n303\t| Condition | Severity | Behavior |\n304\t|-----------|----------|----------|\n305\t| File not found or unreadable | Error | Halt with OS error. |\n306\t| No title found | Warning | Set `title` to `null`. |\n307\t| No `-- Turn 1 --` in any file | Error | Halt — no parseable turns. |\n308\t| Turn number gap | Warning | Record missing numbers. Continue. |\n309\t| Turn 1 has Action section | Warning | Accept and store. |\n310\t| Duplicate turn after combining | Error | Bug in Phase 1. |\n311\t| Section appears twice in one turn | Warning | Append content with `\\n\\n`. |\n312\t\n313\tAll warnings include source file, line number, and description.\n314\t\n315\t---\n316\t\n317\t## 4. Query Categories\n469\t\n470\t### 5.1 manifest\n471\t\n472\tReturns full `manifest.json` content. Recommended first query — tells the agent what data is available, how many turns exist, and which files were produced.\n473\t\n474\t### 5.2 metadata\n475\t\n476\tReturns full `metadata.json` content. Primary source for Title, Description, Background, Skills, and Objective fields in a sequel world.\n477\t\n478\t### 5.3 tracked_state\n479\t\n480\t**Requires `turns` parameter.** For each requested turn, finds the snapshot where `from_turn <= turn <= to_turn` and returns that snapshot's data.\n481\t\n482\tReturns an array of objects:\n483\t\n484\t```json\n485\t[\n486\t  {\n487\t    \"turn\": 15,\n488\t    \"tracked_items\": { \"ViviDevelopment\": \"6\", \"VivianPersonality\": \"Vivian-dominant\" },\n489\t    \"hidden_tracked_items\": { \"Suspicion\": \"0\", \"InvestigationInterest\": \"0\" }\n490\t  }\n491\t]\n492\t```\n493\t\n494\tIf `tracked_state.json` does not exist, returns an error indicating tracked state is not available.\n495\t\n496\t### 5.4 turn_index\n497\t\n498\tReturns full `turn_index.json` content. The agent uses this to scan turn previews and identify turns of interest before drilling in with `turn_detail`.\n499\t\n500\t### 5.5 turn_detail\n501\t\n502\t**Requires `turns` parameter.** Reads specific turns from the original export file using line ranges from the turn index.\n503\t\n504\tReturns an array of objects:\n505\t\n506\t```json\n507\t[\n508\t  {\n509\t    \"turn\": 1,\n510\t    \"action\": null,\n511\t    \"outcome\": \"Full outcome text...\",\n512\t    \"secret_info\": \"Full secret info text...\"\n513\t  }\n514\t]\n515\t```\n516\t\n517\tIf the original source file has been moved or deleted since extraction, returns an error.\n518\t\n519\t### 5.6 The `\"last\"` Alias\n520\t\n521\tAll categories accepting `turns` support `\"last\"`, which resolves to the highest turn number. Can be mixed with numbers: `[1, \"last\"]` resolves to `[1, 22]` for a 22-turn story.\n522\t\n523\t---\n524\t\n525\t## 6. Agent Consumption Workflow\n526\t\n527\t### Bootstrap\n528\t\n529\tThe agent calls `extract_story_data` once at the start, then uses `query_story_data` throughout the field-by-field sequel-world walkthrough.\n530\t\n531\t### Field-by-Field Query Patterns\n532\t\n533\t| Sequel Field(s) | Query Sequence | Rationale |\n534\t|---|---|---|\n535\t| **Title, Description, Background, Objective** | `\"manifest\"` → `\"metadata\"` → `\"turn_detail\"` for first and last turns | Metadata gives raw fields. First/last turn detail shows arc endpoints. Agent synthesizes sequel description. |\n536\t| **First Action** | `\"metadata\"` (objective) → `\"turn_detail\"` for last turn | Sequel picks up where story ended. Agent needs final narrative state. |\n537\t| **Skills, Possible Characters** | `\"metadata\"` (existing skills) → `\"tracked_state\"` at last turn | Skills carry forward. Tracked state reveals final character dispositions. |\n538\t| **NPCs** | `\"turn_index\"` (scan previews) → `\"turn_detail\"` for key turns (early, middle, late) | Turn index previews help identify character-relevant turns. Agent reads Secret Info blocks to determine character roles and final states. |\n539\t| **Tracked Items** | `\"tracked_state\"` at last turn | Direct extraction — exact final values for every tracked item. |\n540\t| **Trigger Events** | `\"tracked_state\"` at last turn → `\"turn_detail\"` for turns with trigger mechanics | Tracked state shows existing triggers. Turn detail provides context. |\n541\t| **Instructions, Author Style** | `\"metadata\"` (background/objective) → `\"turn_index\"` (sample outcome previews) | Agent calibrates narrative voice from preview strings. |\n542\t\n543\t### Context Budget\n544\t\n545\tFor a 250-turn story (worst case):\n546\t\n547\t| Data | Tokens |\n548\t|------|--------|\n549\t| Manifest | ~200 |\n550\t| Metadata | ~500 |\n551\t| Turn index (250 entries) | ~3,000 |\n552\t| Tracked state (last turn) | ~500 |\n553\t| 5-6 individual turn details | ~15,000 |\n554\t| **Total** | **~20,000** |\n555\t\n556\tCompare: loading the raw 250-turn export consumes ~200,000+ tokens.\n557\t\n558\t### Sequel-World Command Update\n559\t\n560\tThe `commands/sequel-world.md` file must be updated:\n561\t\n562\t- Remove the \"read the ENTIRE export\" instruction.\n563\t- Add a step to call `extract_story_data` with the export file path(s).\n564\t- Replace raw export reads with `query_story_data` calls at each field.\n565\t- Add guidance to use `\"turn_index\"` for selecting turns to drill into.\n566\t- Preserve the existing field-by-field walkthrough structure.\n567\t\n568\t---\n569\t\n570\t## 7. Limitations\n571\t\n572\t### What Deterministic Parsing Cannot Do\n573\t\n574\t1. **Cannot summarize narrative arcs.** The agent still reads prose — but now reads targeted turns instead of everything.\n575\t2. **Cannot extract character rosters from prose.** For exports without structured character data in tracked items (like RingOfDis), the agent must read Secret Info via `turn_detail` and identify characters itself.\n576\t3. **Cannot determine character relationships.** Relationships are expressed in narrative, not structure.\n577\t4. **Cannot detect theme or tone.** Semantic properties of prose, not parseable.\n578\t\n579\t### Where It Helps Most\n580\t\n581\t- **Eliminates \"read the ENTIRE export.\"** Context usage drops by an order of magnitude.\n582\t- **Prevents hallucination of tracked item values.** Exact final state from the parser, not the agent's fuzzy recall.\n583\t- **Prevents early/late state confusion.** Per-turn snapshots show what was true when.\n584\t- **Prevents character name confusion.** Tracked item strings are exact as written.\n585\t\n586\t### Edge Cases\n587\t\n588\t| Scenario | Behavior |\n589\t|---|---|\n590\t| Export with no tracked items (RingOfDis) | `tracked_state.json` not written. Manifest: `has_tracked_items: false`. Agent falls back to `turn_detail`. |\n591\t| Single-turn export | Works correctly. One-entry turn index. |\n592\t| Malformed turn delimiters | Parser extracts what it can. Warnings in manifest. |\n593\t| Empty tracked item values | Stored as `\"\"`. |\n594\t| Very long tracked item values | Stored verbatim, no truncation. |\n595\t\n596\t---\n597\t\n598\t## 8.
